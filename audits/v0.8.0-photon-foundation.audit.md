## Detailed findings

### PHOTON-AUDIT-006
Status: CONDITIONAL PASS  
Severity: MEDIUM  
Claim being audited: Capture and escape termination represent physically meaningful photon outcomes without introducing material finite-domain bias.  
Independent derivation/reference: The Schwarzschild horizon in the adopted normalization is exactly `r=r_s`, i.e. `r̄=1`. Standard Schwarzschild coordinates become singular there, so an exterior numerical cutoff is a legitimate implementation device but is not itself the physical horizon. Scattering observables are asymptotic quantities and therefore require finite-boundary convergence checks.  
Implementation behavior: The null solver uses a default capture cutoff `1.0005 r_s`. `PhotonSubsystem` generally uses a finite outer boundary smaller than the null solver class default and enlarges it only relative to launch radius.  
Evidence: The capture cutoff is documented as a near-horizon numerical threshold, and direct trajectories classify consistently in the tested domain. Weak-field validation at large launch radius also behaves correctly. A systematic outer-boundary convergence matrix is absent.  
Why this matters: A correct local equation can still produce a biased measured deflection if incoming/outgoing directions are sampled too close to the gravitating body.  
Required developer action: Add a deterministic finite-boundary study over several `maximumRadius` values and specify the boundary used when quoting a deflection accuracy.  
Re-test required: Yes — compare the same impact parameters with successively larger outer boundaries and require observable convergence.

### PHOTON-AUDIT-007
Status: CONDITIONAL PASS  
Severity: LOW  
Claim being audited: The reported relative null error is a useful numerical diagnostic.  
Independent derivation/reference: For the null condition `g_{μν}k^μk^ν=0`, a scale formed from the sum of absolute magnitudes of the contributing metric terms is a reasonable dimensionless residual normalization because it does not divide by the cancellation result itself.  
Implementation behavior: The solver computes the absolute residual and divides its magnitude by `|timeTerm|+|radialTerm|+|angularTerm|`.  
Evidence: The metric terms are constructed directly from the current normalized state and conserved constants.  
Why this matters: Relative residuals can remain small while the absolute residual changes significantly between regions with very different term magnitudes.  
Required developer action: Retain both diagnostics and avoid any documentation claiming the relative residual alone proves global trajectory accuracy.  
Re-test required: Only if the diagnostic definition or acceptance thresholds change.

### PHOTON-AUDIT-008
Status: FAIL  
Severity: HIGH  
Claim being audited: Photon motion advances correctly across the documented UI mass range under the production runtime clock.  
Independent derivation/reference: In the adopted normalization, the time scale is `t_s=r_s/c=2GM/c³`. Therefore a fixed SI interval corresponds to `Δλ̄` proportional to `1/M` when the runtime chooses the affine normalization through `siTimeToNormalized`. A solver with finite maximum normalized work per call must either receive mass-dependent smaller calls or internally split the request.  
Implementation behavior: `PhotonSubsystem.update(deltaSeconds)` computes `deltaAffine=this.units.siTimeToNormalized(deltaSeconds)` and passes it to one `advanceAffine` call. `advanceAffine` rejects requests needing more than `maximumSubsteps`. General photon settings allow at most `4096×0.02=81.92`; Light Bending allows at most `4096×0.005=20.48`.  
Evidence: With the fixed ordinary runtime step `1/240 s`, one solar mass corresponds to about `Δλ̄=422.96`. This requires roughly 21,148 general-photon substeps or 84,592 Light-Bending substeps, both greater than 4,096. The corresponding approximate minimum masses for one-call success are `5.163 M☉` and `20.652 M☉`. The UI accepts `1 M☉`.  
Why this matters: Valid user inputs can make the advertised photon physics fail immediately for numerical scheduling reasons unrelated to the geodesic. This directly affects trajectories and observables.  
Required developer action: Redesign the runtime/solver interface so large normalized advances are safely divided into bounded solver calls, or impose and document a scientifically justified mass/runtime restriction. The preferred correction is a solver-safe stepping contract rather than narrowing the physical UI range without necessity.  
Re-test required: Yes — at minimum run general and Light-Bending photon scenarios at `1`, `5`, `10`, `20`, `100`, `4×10⁶`, and `10¹⁰ M☉` over several runtime scales and verify no scheduler-induced numerical failure.

### PHOTON-AUDIT-014
Status: FAIL  
Severity: HIGH  
Claim being audited: The existing timelike Schwarzschild simulator remains scientifically valid over the documented supported UI mass range.  
Independent derivation/reference: The same normalized-time scaling applies to proper-time advancement: `Δs = Δτ/t_s`. The timelike solver's per-call work budget is finite.  
Implementation behavior: `SchwarzschildGeodesicSystem` defaults to `maximumNormalizedStep=0.02`, and the normal subsystem uses 128 maximum substeps unless changed by the advanced control. This gives a default maximum normalized advance of `2.56` per call.

Why this matters: A user can choose a physically ordinary stellar-mass Schwarzschild object and receive a numerical failure caused by runtime discretization, contradicting the stated support range.  
Required developer action: Fix the shared stepping contract and validate the full declared range for timelike motion as well as photons.  
Re-test required: Yes — low-mass timelike circular, plunging, and scattering cases must run without scheduler-induced failure and retain the expected conservation/convergence behavior.

## Independent derivation notes

### Schwarzschild convention

The audited code uses

```text
r_s = 2GM/c²
M_geo = GM/c² = r_s/2
r̄ = r/r_s
t̄ = ct/r_s
f(r̄) = 1 - 1/r̄
```

For an equatorial null geodesic with signature `(-,+,+,+)`,

```text
0 = -f (dt̄/dλ̄)² + f⁻¹ (dr̄/dλ̄)² + r̄² (dφ/dλ̄)²
E = f dt̄/dλ̄
L = r̄² dφ/dλ̄
```

hence

```text
(dr̄/dλ̄)² = E² - f L²/r̄²
```

and differentiation gives

```text
d²r̄/dλ̄² = L²(1/r̄³ - 3/(2r̄⁴)).
```

The implementation matches these equations.

### Photon sphere and critical impact parameter

A circular null orbit requires both radial velocity and radial acceleration to vanish. The acceleration equation gives

```text
r̄_ph = 3/2.
```

The null first integral then yields

```text
b_crit/r_s = L/E = 3√3/2 ≈ 2.598076211353316.
```

Linearizing radial motion around `r̄=3/2` gives a positive perturbation coefficient, confirming instability rather than neutral stability.

### Weak-field reference

In physical units,

```text
α = 4GM/(bc²) + O((GM/bc²)²).
```

Since `r_s=2GM/c²`, the audited normalized first-order relation is

```text
α ≈ 2/(b/r_s).
```

Independent integrations show the relative difference decreases as the impact parameter grows, as required for a valid weak-field limit.

## Scientific release verdict

FAIL

### Release blockers

- **PHOTON-AUDIT-008 (HIGH):** production runtime/affine mapping can force photon `NUMERICAL_FAILURE` for valid low-mass inputs; Light Bending is affected over an even larger low-mass range.
- **PHOTON-AUDIT-014 (HIGH):** pre-existing timelike runtime/normalized-step mismatch contradicts the documented `1–10¹⁰ M☉` supported mass range.
- **PHOTON-AUDIT-015 (MEDIUM):** user-facing unit wording falsely describes the solver as remaining in SI units during integration.

### Non-blocking findings

- Photon-sphere, critical-impact-parameter, null-geodesic, weak-field, near-critical, convergence, renderer-isolation, bundle-independence, Inspector, and OFF-gate checks passed under the audited assumptions.
- Repository validation should add perturbation, multi-impact weak-field, explicit convergence, and finite-boundary tests to make those passes durable.

### Numerical limitations

- Schwarzschild coordinates are used only outside the horizon; capture is terminated at `1.0005 r_s` rather than integrated through the coordinate singularity.
- Scattering/deflection measurements are made at finite boundaries, not mathematical null infinity.
- The null relative-residual metric is useful but should be interpreted together with absolute residual and observable convergence.

### Assumptions

- Fixed analytic Schwarzschild spacetime; no backreaction, spin/Kerr terms, radiation reaction, plasma/accretion physics, or full image-plane ray tracing.
- Equatorial test-particle/test-photon motion.
- The audited numerical reference calculations use the same physical convention but not the production RK4 implementation as the accuracy reference.

### Required follow-up

1. Repair the runtime-to-solver stepping contract for both photon and timelike subsystems.
2. Validate the documented mass range, especially `1–200 M☉`, across normal and high runtime scales.
3. Add photon sphere perturbation, `b=25/50/100`, `h/h/2/h/4`, and finite-escape-boundary regression tests.
4. Correct the SI-vs-normalized unit language and refresh stale project metadata.
5. Return the developer fix commit SHA for independent re-audit.
