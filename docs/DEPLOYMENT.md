# GitHub Pages deployment

## Production target

The expected production URL is:

`https://ogw07222-tech.github.io/gr-simulator/`

GitHub Pages serves this project below `/gr-simulator/`, not at the account root. `vite.config.js` therefore selects `/gr-simulator/` only when `GITHUB_PAGES=true`. Local development, ordinary builds, Codespaces, and localhost continue to use `/`.

Do not add independent hard-coded asset prefixes. JavaScript and CSS URLs are generated by Vite from the configured base. The build validator checks every local `src` and `href` emitted into `dist/index.html`, verifies the expected prefix, and confirms that each referenced file exists.

## Automatic deployment

`.github/workflows/deploy-pages.yml` runs for every push to `main` and can also be started manually. The build job checks out the repository, installs the locked dependencies with `npm ci`, runs lint and unit tests, configures Pages, and performs a Pages-base production build. Only a successful build is uploaded and passed to the deployment job.

The workflow uses the minimum deployment permissions: read-only repository contents plus Pages and OpenID Connect write access. The deploy job targets the protected `github-pages` environment, and a concurrency group prevents overlapping production deployments.

Inspect deployment status under the repository's **Actions** tab by opening the **Deploy GitHub Pages** workflow. To rerun manually, choose **Run workflow**, select `main`, and confirm the run.

Deployment must not be described as successful until both the `build` and `deploy` jobs complete successfully and the environment reports its URL.

## Required repository setting

The repository owner must open **Settings → Pages → Build and deployment → Source** and select **GitHub Actions**. No branch-based Pages publishing directory should be configured.

## Local production preview

```bash
npm run build
npm run preview -- --host 0.0.0.0
```

`vite preview` is only a local production-build preview server. It is not the production hosting server.

To reproduce the Pages asset layout locally, set `GITHUB_PAGES=true` for the build before starting the preview. Open the preview through `/gr-simulator/` and verify that the browser reports no failed asset requests or console errors.

## Custom domain

A custom domain can be added later through **Settings → Pages**. At that time, add the domain's `CNAME` file under `public/`, update the production base strategy if the site moves to the domain root, and verify HTTPS/DNS before changing documented URLs. The current workflow intentionally targets the repository subdirectory.
